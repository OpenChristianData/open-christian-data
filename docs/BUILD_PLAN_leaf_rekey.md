# Build Plan — NSH chain leaf-rekey (zero re-OCR)

**This document is the canonical build tracker** for re-architecting the NSH OCR
download→S2 chain onto leaf-keyed addressing. It is the single source of truth for what is
built, in flight, and blocked. Update §0 on every landing — check a box only when its tests
are green and the work is committed (cite the commit). American English; relative paths.

Derived from the design doc `plans/2026-06-13-nsh-leaf-rekey-design.md` (v3, gitignored —
force-add for durability), which carries the full rationale, the measured evidence, and the
three Codex adversarial reviews (all NEEDS-CHANGES, all folded in). Read the design doc
before any step.

## Why this exists (one paragraph)

Every per-page artifact in the chain is keyed on `page_native_id` (the image **filename
stem**) and per-page skip/currentness is gated on a **volume-global** `manifest_id`. Both
are rename-volatile: the 2026-06-09 phantom-page fix renamed ~half the body files, flipped
each volume's manifest_id, and the next run re-OCR'd vol_01 from scratch (10.5h) despite the
OCR existing on disk. The fix keys each page on `leaf_num` (the stable join coordinate the
canonical manifest already owns) with `source_payload_sha256` as the immutable reuse key —
so renames and leaf-number corrections never trigger a redo.

## 1. Common working protocol (every prompt references this)

**Orchestration (CODEX-05):** the session orchestrates; Codex writes code; the session
reviews the diff (CODEX-04 `git diff HEAD`), reads each file Codex claims it wrote (CODEX-01),
runs `py -3 .claude/standards_check.py <touched .py>` + the fast suite, then commits
pathspec-scoped to exactly its files (GIT-01b — a parallel session may stage unrelated work).
Codex never commits. Use `--dangerously-bypass-approvals-and-sandbox` (read-only/workspace-write
fail on this machine — see `CLAUDE.local.md`); smoke-test before dispatch (CODEX-03).

**Read first, every step:**
- `plans/2026-06-13-nsh-leaf-rekey-design.md` — the spec (v3). The constraint contract is §1; the stage changes §3–§4; this step's row in §5.
- This tracker §0 + §2 (acceptance for the step).
- Newest `LAST_SESSION_*.md` in the repo root.
- `build/lib/nsh_leaf_model.py` (the accessor; TEST-08 gate forbids raw `manifest["pages"]` reads outside it) and `build/lib/ocr_store_paths.py` (store roots).
- Refresh disk state: `py -3 build/tools/ocr_pipeline/ocr_inventory.py status`. The OCR stores are gitignored — **disk is the only ground truth**; git gives a false all-clear (VER-01).

**Hard constraints throughout (design §1):**
- **C1 ZERO re-OCR.** No successfully-OCR'd page is run through an engine again. If a step seems to need re-running an engine on existing output, STOP and surface it.
- **C3 content is ground truth** — reuse is decided by `source_payload_sha256`, never filename or volume hash.
- **C5 current manifest wins** — the leaf coordinate is always re-derived from the current `vol_NN.manifest.json`; never trust a stored `canonical_leaf_id` for a join.
- American English in all repo content; schema updated before any data write (PIPE-14); after multi-edit on any `.py`, `py -3 -m py_compile <file>`; verify migrations by reading files on disk, not git status; keep the full suite green and TEST-08 clean; do not use `--no-verify`.
- Test commands per `AGENTS.md` (always `-p no:cacheprovider`): fast = `py -3 -m pytest -p no:cacheprovider -m "not slow" -n auto -q`; full (before commit) = `py -3 -m pytest -p no:cacheprovider -q`.
