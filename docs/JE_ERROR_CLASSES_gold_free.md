# JE error classes — gold-free detection & correction catalogue (U11b)

**What this is.** The Jewish Encyclopedia (1906) gold is a one-time *teacher*: it has a human
transcription, so it reveals the full catalogue of error phenotypes that appear when the panel OCR
is scored against truth. NSH and every future text will have **no** such reference (ADR-0015). So
for each error class the gold reveals, this doc answers two questions a reference cannot answer at
NSH runtime: (1) what observable, gold-free signal would tell us the error occurred, and (2) how
would we correct it gold-free — or, when we cannot, how do we detect that it must not auto-publish?
The uncaught remainder per class is the **risk register NSH inherits**.

**Authority / scope.** Generated by `build/tools/ocr_pipeline/classify_je_errors.py` over the
quarantined JE Vol 2 surrogate (34 WCT pages, 11 articles, 24,649 aligned pairs). Read-only on the
corrector package — this is measurement, not a new corrector module. Cross-referenced from
`docs/NSH_PROJECT_STATE.md`; measurement numbers are owned here and in `docs/JE_SURROGATE_FINDINGS.md`.
ADR-0014 / ADR-0015 are locked and not reopened. **Every rate below is an aligner-mediated floor,
never a calibration target** — see the oracle-limit finding.

---

## Decision brief

- **The gold-free pipeline is NOT ready to auto-publish NSH unflagged.** Even on the cleanest
  measurable stratum (L0, all engines attest, drift excluded) the false-correction floor is
  **~12–18%** — two to three orders of magnitude above the ADR-0015 0.1% bar.
- **The binding constraint is the measurement oracle, not (yet) the corrector.** The
  Needleman-Wunsch aligner injects mismatch at a rate comparable to the true OCR-error rate, so the
  surrogate cannot *measure* false-correction below ~10–15%. We literally cannot certify the
  corrector at 0.1% with this oracle, whatever its true quality.
- **The `far_*` classes are largely aligner artifacts, not OCR phenotypes — and they do not transfer
  to NSH.** Spot-check evidence: `'as' → 'Steinschneider'`, `'to' → 'Aquilino'`, `'1138' → 'Vatican'`.
  OCR cannot turn a 2-char word into a 14-char proper noun; the aligner mis-mapped the reference
  token. NSH has **no aligner** in its production path (the corrector consumes a frozen WCT), so
  these are oracle-error phenotypes, not NSH error phenotypes. The genuine NSH-relevant OCR
  phenotype lives in `real_minor`.
- **At the single position, the gold-free signals barely discriminate.** Each fires at roughly the
  same rate on a *correct* token as on an erroneous one (recall ≈ false-alarm). The one high-recall
  signal — low attestation confidence — fires on **82%** of clean tokens, so it cannot gate
  auto-accept.
- **The biggest NSH blind spot:** an error where all engines share the misread (no engine
  disagreement) **and** the wrong reading is itself a real lexicon word (lexical) **and** it is latin
  script **and** the position is fully attested. No gold-free signal in the toolbox sees it. This is
  the Class-B confident-error case; it depends on M3 protected-class routing, which is *fail-safe*
  (it over-routes, costing coverage, never correctness) but weak as a discriminator.

## Classification (all non-empty articles)

Classes (U11 starting thresholds, `confusion_dist` cut at 0.6; tunable):

| Class | Count | % of pairs | spot-check (15/class, complete article) |
|---|---|---|---|
| clean | 12,114 | 49.1% | n/a — `match` is True |
| real_minor | 2,687 | 10.9% | labels correct; **mixed**: real OCR errors (`before→fore`, `'Emeḳ'→'‘Emek'`) + short-word alignment slips |
| far_isolated | 1,195 | 4.8% | labels correct; **~all alignment artifacts** (`'as'→'Steinschneider'`, `'a'→'has'`), not catastrophic OCR |
| far_clustered | 8,653 | 35.1% | labels correct; **alignment drift runs** (`'1138'→'Vatican'`, `'Angelo'→'by'`) |

**Complete-only cut** (7 articles with no missing WCT page; excludes `apologists`, `apostasy`,
`atonement` whose missing pages force-misalign reference text): 10,248 pairs — clean 47.6%,
real_minor 12.3%, far_isolated 4.3%, far_clustered 35.7%. The distribution barely moves, which
overturns a natural hypothesis: **clustered drift is not a partial-article artifact** — the aligner
produces ~36% clustered mismatch even on perfectly complete two-column pages. The headline coverage
and FCR numbers below use the complete-only cut as the de-noised view.

**Spot-check result, stated plainly.** The class *labels* are assigned correctly per the threshold
rule (15/15 per class). But the *semantic* prior that `far_isolated` ≈ "real catastrophic OCR error"
(prompt context line, ~5%) **does not hold**: a single reference token mis-mapped by the aligner,
with its neighbors correctly mapped, produces exactly the far_isolated signature. By length-ratio
and content, the far_isolated and far_clustered classes are dominated by alignment-oracle error, not
OCR error.

## Error-class catalogue — gold-free detection & correction (the deliverable)

| Class | Phenotype (real examples) | Gold-free tell | Gold-free remedy | Residual risk |
|---|---|---|---|---|
| **formatting** | Case/punctuation/diacritic-only differences between the raw OCR token and the printed form: `'Emeḳ' / '‘Emek'`, headword small-caps vs body case. | None needed — it is not an error. The aligner's `match` and the corrector's normalization already fold these. | Preserve the **raw** reading; normalize only for comparison. The harness compares raw text, so a normalized "fix" would register as a false correction (see `generate_je_gold.py` docstring). | None. |
| **real_minor** | Close-but-wrong, correctly aligned. Genuine OCR: `before→fore`, `contengono→conten-` (hyphenation), dropped/added char. NSH **will** reproduce this. | **Weak.** Non-lexicality fires on 45% (but 41% of *clean* tokens too); engine disagreement 22%; low-confidence 88% (but 82% of clean). No signal is a clean discriminator. | L0/L1 column-vote can recover the cases where ≥2 engine families carry the right graphemes. Where families share the slip, route. | The ~47/1263 (3.7%) uncaught: single-candidate, lexical, latin, attested — a real-word OCR error that reads as clean. |
| **far_isolated** | Mostly an **aligner artifact**: one reference token mapped to an unrelated OCR position (`'as'→'Steinschneider'`, `'a'→'has'`). Length ratio alone reveals it. | Low-confidence (94%) and non-lexicality (42%) fire, but with no better discrimination than on clean tokens. The artifact has no consistent observable signature. | Not a correction target — there is nothing to correct (the OCR position was *correctly* read; the *alignment* was wrong). For NSH this class largely vanishes (no aligner). | Negligible **for NSH** — it is oracle noise. The residual is the small true-catastrophic-OCR subset, which engine-disagreement catches when present. |
| **far_clustered** | **Aligner drift runs** through dense / two-column / bibliographic zones: consecutive reference tokens each mis-mapped (`'1138'→'Vatican'`, `'Angelo'→'by'`). 35% of all pairs. | Observable proxies: low confidence (92%), engine-disagreement density, non-latin zones. But "a neighbor failed" is **gold-defined and unobservable** at NSH runtime — it is *not* a usable gold-free signal. | None gold-free at the token level. The structural fix is a better aligner / reading-order model in the **oracle**, not the corrector. Route on confidence + disagreement density. | Oracle measurement noise, not an NSH publishing risk. Its main harm is **inflating the measured FCR floor** so the 0.1% bar cannot be tested. |

**Why the `far_*` rows read "not an NSH risk":** the corrector never sees an aligner. It consumes a
frozen WCT page and emits a corrected-page sidecar. The aligner exists *only* in the JE surrogate, to
score OCR against the human transcription. So aligner-induced mismatch teaches us about the oracle's
resolution limit, not about what NSH will publish. The NSH-relevant phenotype is `real_minor`.

## Gold-free coverage per class (measured, complete-only / de-noised)

Per-signal **recall on errors** vs **false-alarm on clean tokens**. Discrimination = recall − FA;
near zero means the signal cannot tell an error from a correct reading.

| Signal | real_minor | far_isolated | far_clustered | clean (false-alarm) |
|---|---|---|---|---|
| engine-disagreement (`candidate_set`>1) | 22.2% | 14.2% | 16.4% | **14.9%** |
| non-lexical (in-corpus lexicon) | 44.7% | 42.1% | 43.5% | **40.9%** |
| protected-class (`protect.py`) | 20.8% | 22.7% | 23.9% | **17.4%** |
| non-latin script | 1.3% | 3.8% | 3.9% | **2.6%** |
| low confidence (`alignment_confidence`<0.99) | 88.2% | 94.1% | 92.2% | **81.6%** |
| **caught by ≥1 signal** | **96.3%** | 98.2% | 98.0% | **93.5%** |
| **uncaught (NSH blind spot)** | 3.7% (47) | 1.8% (8) | 2.0% (74) | 6.5% (316) |

- **LM-low (M7/M8): skipped, with reason.** M8 is an L3-*candidate* rescorer, not a per-position
  low-probability flagger; there is no exposed "this position is improbable" signal to read. And the
  in-corpus training corpus is ~10k clean tokens (complete-only) — far too thin to train a
  discriminating word-bigram LM (M7). Running it would produce a number with no inferential value.
- **The headline recall is a trap.** `caught ≥1` reaches 96–98% on errors — but **93.5% on clean
  tokens too**. Routing everything "caught" would route 93% of correct readings, collapsing
  coverage. The high recall is bought almost entirely by `low_confidence`, whose 82% clean
  false-alarm makes it useless as an auto-accept gate on a 5-engine panel (requiring all 5 to attest
  is stringent; most positions miss one).
- **Per-`script` breakdown:** errors are 96–97% latin in every class (real_minor 1263: 1225 latin /
  36 unknown / 2 greek; far_clustered 3662: 3349 latin / 270 unknown / 23 hebrew / 20 greek). The
  worst-covered bucket is **`unknown` script** (positions the script classifier could not label),
  which clusters in the far classes.
- **Per-`zone_type` breakdown is degenerate — and that is itself a finding.** Every aligned pair is
  `body` (24,649/24,649). The aligner routes running headers, printed folios, and Hebrew/Greek
  apparatus to `positions_unaligned` — they **never produce an aligned pair**. So the zones most
  likely to be mis-OCR'd are *invisible to this measurement entirely*. Their risk is unmeasured, not
  zero; the apparatus/header strata must be certified by a separate path (geometry + script routing),
  not inferred from this catalogue.

## Corrector FCR on the trustworthy subset (secondary cross-check)

`correct_position` + `decide` (all levels accept-enabled, permissive) on every position **except
far_clustered**. Complete-only; FCR exact and normalized; powered = auto-accepted ≥ 2995 (ADR-0015).

| Level | auto_accepted | coverage | FCR exact | FCR normalized | powered? |
|---|---|---|---|---|---|
| L0 (≥2-family consensus) | 5,242 | 1.00 | 24.6% | 21.8% | yes |
| L1 (column-vote composed) | 1,117 | 1.00 | 47.2% | 41.1% | no |

Restricted further to `alignment_confidence ≥ 0.99` (all engines attest):

| Level | auto_accepted | coverage | FCR exact | FCR normalized | powered? |
|---|---|---|---|---|---|
| L0 | 1,050 | 1.00 | 18.4% | 15.3% | no |
| L1 | 13 | 1.00 | (n too small) | — | no |

**Both trust filters agree on the ordering L0 < L1** (L0 false-correction is roughly half L1's under
both the cluster-exclusion filter and the attestation filter). All-articles numbers are close
(L0 22.6%/20.1% exact/norm, powered; conf≥0.99 L0 13.8%/11.9%, not powered). The normalized FCR
sits ~2.5–3 pp below exact, so case/punctuation accounts for only a small slice — the bulk is
real disagreement (much of it the alignment artifact described above leaking into the denominator
via far_isolated and short-word real_minor slips). **The de-noised L0 false-correction floor is
~12–18%; it is a floor, not a target, and the aligner sets it.**

## Verdict — NSH readiness

**Covered (already defended by the existing stack):**
- **Formatting** — fully handled; raw preserved, normalize-for-compare only.
- **Engine-disagreement-visible OCR errors** — where ≥2 families carry the right graphemes, L0/L1
  column voting recovers them; the WCT `candidate_set` is the gold-free tell.
- **Protected classes** (names, numbers, dates, Scripture refs, non-latin) — M3 routes them before
  any score is read. This is **fail-safe**: it over-routes (17% clean false-alarm) so it costs
  coverage, never correctness. As a *safety* gate it works; as a *discriminator* it is weak.

**Under-defended:**
- **Class-B confident errors** (`real_minor`, all engines share the misread, the misread is a real
  word, latin, attested). These are exactly the errors no gold-free signal sees, and they depend on
  M3 protected routing — which is not wired into the measured `measure_page` path (it hardcodes
  `protected_class="none"`), so the U11 "0 leaks" result is vacuous, and the real protective value
  is unmeasured here. M15's flag-until-certified policy must hold L1–L3 (and arguably L0 on NSH)
  flagged until a human transfer sample certifies the stratum.
- **Apparatus / header / non-latin zones** — never enter the aligned set, so their error rate is
  unmeasured. They cannot be certified from this surrogate.

**Biggest blind spot:** the silent real-word substitution that every engine shares — undetectable by
disagreement, by lexicality, by script, by confidence. On JE complete-only this is the ~3.7% of
real_minor (≈47 positions) that no signal catches, scaled up by the unmeasured apparatus zones.

**Readiness call:** **Not ready to auto-publish NSH unflagged, and — more fundamentally — not yet
*certifiable* against the 0.1% bar with the current oracle.** Before the gold-free pipeline can be
declared NSH-ready, the prerequisite is **a measurement oracle that floors below ~10% false
correction** — either (a) a higher-fidelity JE alignment (confidence/agreement-gated, reading-order
aware, or restricted to a hand-verified subset) so the aligner stops injecting mismatch at the OCR-
error rate, or (b) the ADR-0015 human-adjudicated Schaff-Herzog transfer sample, which has no
aligner in the loop. The corrector tiers may well be fine; this surrogate cannot prove it at the
required resolution. M15 should therefore ship with **L0+ flagged-until-certified for NSH**, and the
certification gate should consume the human transfer sample, not the aligner-mediated JE FCR.

## Reproduce

```
py -3 build/tools/ocr_pipeline/classify_je_errors.py
```

Reads the quarantined WCT + aligner gold read-only; writes the full per-class / per-signal report to
gitignored `prompts/je-error-classes-report.json`. Unit tests: `tests/test_classify_je_errors.py`.
