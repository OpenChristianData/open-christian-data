# Corpus Verification Workbench

Corpus Verification Workbench (CVW) is a Windows-only, local, read-only viewer for
retained sources and current nonaccepted TEI candidates. It has exactly three user tasks:

- **Library** lists ordinary works and current candidate-session availability from declared sidecars or an explicitly selected historical WorkCatalog.
- **Read** opens the validated retained source and generated TEI for a selected work.
- **Compare** shows the source and TEI side by side at the same time.

CVW is a viewing surface only. It does not reconstruct text, change source or IR files, or decide
whether a candidate is accepted.

## Inputs and validation

The service reads declared work/acquisition sidecars and caller-selected candidate directories.
An explicit `--catalog PATH` selects the historical WorkCatalog route during migration.
Both routes remain supported; missing sidecars never cause an implicit fallback. CVW creates
no durable candidate root, second registry, or acceptance state.

Each candidate directory is a current-session input with exactly this shape:

```text
candidate-directory/
├── package/
├── validation.json
└── text-quality.json  (new runner invocations)
```

`package/` contains the candidate package and its manifest. `validation.json` is the deterministic
runner-produced sidecar. It binds the candidate-manifest digest, source-manifest digest,
validation-report digest, pass status, and validator identity. CVW verifies those bindings, the
required package members, the retained-source identity and hashes, and the WorkCatalog route
before displaying anything.

New runner invocations also retain an advisory character screen in `text-quality.json`.
CVW verifies its hash from `validation.json`, candidate/source bindings, and complete
input inventory. Staging copies this sidecar unchanged from beside the validation
record. Historical candidates without the sidecar remain supported. Findings and
unsupported coverage follow the [text-quality review procedure](../docs/SOURCE_PREFLIGHT.md#advisory-text-observations).

Admission validation is fail-closed. Missing, stale, mismatched, failed, noncanonical, or tampered package,
source-manifest, or validation evidence prevents the service from starting or the work from being
shown. Candidate directories are read-only inputs selected by the caller and are not copied into
the repository.

For an already-built flat six-member package with an existing full canonical
validation record, stage an unchanged copy into a fresh external directory:

```powershell
py -3 -m cvw_app.stage_candidate --package "<flat-package>" --validation "<existing-validation.json>" --destination "<fresh-external-candidate-directory>" --repository-root "<authority-checkout>"
```

The helper copies the package and validation bytes, checks the exact candidate,
source manifest, retained authorities and validation bindings through the existing
CVW loader, and promotes the wrapper only on success. It never runs a converter
or validator, updates WorkCatalog, or changes the original inputs. Destinations
must be absent, outside the repository and governed storage, and outside the
input package. Existing directories and reparse-point inputs are refused.
Validation summaries, report digests, and review receipts cannot substitute for
the full runner-produced record. If that record was not retained, recover it
from the original validation run; this helper cannot manufacture it. Source
mismatches require separate owner resolution and are never resealed here.
Successful staging proves packaging and existing evidence integrity only;
declared-library or historical WorkCatalog route admission remains separate.

For a currently installed accepted edition whose historical candidate no longer
matches the library, prepare an unchanged review copy through the normal runner:

```powershell
New-Item -ItemType Directory -Path ".tmp_audit/cvw-session"
py -3 -m build.tools.prepare_cvw_review --acceptance "library/works/<work>/forms/<form>/editions/<edition>/acceptance.json" --manifest-directory ".tmp_audit/cvw-session/<work>" --destination "<fresh-external-candidate-directory>"
```

The helper revalidates the existing acceptance, binds the current work and
acquisition, and copies the promoted master's exact bytes. Its independent check
rejects changed source membership, acceptance evidence, or master text. This
creates a nonaccepted viewing package, not a new acceptance or reconstruction.
Keep its session manifest directory while viewing; it remains a required bound
input. Use the resulting directory with the ordinary `--candidate-dir` option.

The supported sample-first admission route is generated by the historical
WorkCatalog writer, `build.tools.count_dataset_records --legacy-catalog`, with
repeatable `--reconstruction-evidence`
`SOURCE_ID WORK_ID CANDIDATE_PACKAGE VALIDATION_PATH` arguments. The generator resolves the
source manifest under `sources/` and derives the transient WorkCatalog row from its verified,
independently maintained policy identity; it does not create a second registry or modify `data/`
or `ir/`. `CANDIDATE_PACKAGE` is the flat `package/` directory, while the launcher receives the
candidate directory that contains both `package/` and `validation.json`. A physical multi-part
work is admitted only when every expected, distinct source member is supplied with matching
source-local identity-resolution evidence; unrelated manifests with matching metadata fail closed.

The declared-library route matches a candidate's primary-source authorities to the acquisition's
selected `source_path` when that path identifies one retained member. A retained ZIP package and
support files remain hash-bound evidence without being mislabeled as textual sources. For an
ordered retained-member-set manifest, or when `source_path` names no single retained member, the
candidate must match the complete retained member set.

Keep the admitted inputs unchanged while reviewing. Exact text, original image bytes, and
image derivatives recheck current member bytes when requested. Existing cached Read/Compare
text projections can still show previously admitted content if a member is edited without
changing its declared identity; they are not a fresh-byte attestation. Relaunch after changing
an input. The viewer does not silently update governed hashes to accommodate changed files.

## Reading and comparison

The Library loads bounded summary pages (up to 50 works). **Load more texts**
discovers the remaining rows; Library search and state filters apply to the entire
admitted library, including work IDs and accent-insensitive title/creator matches. Direct Read/Compare links load their exact work independently of the
Library summary. Large source/member pickers use bounded search and page
controls while retaining the exact selected artifact.

API clients use `/api/review/v1/works?view=summary&offset=0&limit=50`, then the
returned `page.next_offset` and `catalog_version`. Work details are at
`/api/review/v1/works/{slug}`; exact selections use paired `source_artifact` /
`source_version` and `tei_artifact` / `tei_version` parameters. Artifact discovery
is at `/api/review/v1/works/{slug}/stages/{stage}/artifacts`, approved-root
discovery at `/api/review/v1/roots`, and correspondence mappings at
`/api/review/v1/works/{slug}/correspondence?correspondence_source={id}`.
Discovery pages disclose totals and omissions; retain the catalog version across
pages. A changed admitted manifest requires relaunch. The legacy no-query
`/works` response remains supported but can exceed the unchanged 512,000-byte
response cap; pagination parameters without `view=summary` are rejected.
Stage and Compare requests may add `auto_page=true` to return the single bounded
segment containing each recorded location in the initial response; without it,
multi-segment requests retain the `page-required` response.

Validated source and TEI are rendered into safe readable views. The existing `pdf-native` and
`image-facsimile` presentations remain available for scanned evidence.

One source-specific alternative presentation is enabled for the exact retained Barnes SWORD
zCom route (`barnes-crosswire-sword-v1.1`, work `barnes-nt-notes`, ticket `37c-066`). It verifies
the manifest-bound Barnes ZIP and its declared index, compressed data, block index, and module
configuration before showing the 8,246 original carriers in numeric source-slot order. Those
slot numbers are not Bible references and no book/chapter/verse mapping is inferred. Invalid
UTF-8 is shown as the carrier's exact bytes in hex; XML-incompatible characters are visibly
escaped and warned about. All other ZIP sources continue to use `unsupported-binary`; this is
not a general ZIP reader and does not change candidate, acceptance, rights, or publication state.

Compare is unlinked by default. CVW shows both panes without guessing a correspondence from IDs,
labels, positions, or text. Linked navigation or correspondence is shown only when the candidate
explicitly supplies the corresponding evidence; absent or uncertain correspondence is labeled
honestly.

Long artifacts use bounded Previous/Next controls. Read may show up to the service maximum per
request; Compare deliberately requests one atomic segment per pane so the combined response stays
within the same size bound. The two Compare panes page independently.

Readable HTML/ThML and TEI tables preserve explicit cells and rows, including
blank cells and nonbreaking spaces, when a table contains any explicit cell.
HTML `colspan`/`rowspan` and TEI `cols`/`rows` support positive decimal spans
up to 1,000 columns and 65,534 rows. Default spans of one are omitted; no cells
are invented or expanded into a grid. Malformed, duplicate HTML, zero, and
out-of-range spans reject the selected readable artifact rather than silently
flattening it; exact-byte access remains available. Special zero-rowspan
row-group behavior and broader table styling are not supported.

After an exact source/TEI Compare, **Copy exact reviewed identity** copies a deterministic JSON
handoff containing the work ID, explicit source artifact/version/path/digest, TEI artifact and
candidate-package digests, and validation/source-manifest digests. It creates no decision and
stores no review or acceptance state.

An exact Compare URL may add `focus=agent` for the compact presentation. The same content,
warnings, and independent pane navigation remain; **Compare controls** contains the normal
controls and **Return to normal Compare**. Human Compare defaults remain unchanged.

In agent Compare, supported native images initially request an identity-bound orientation
preview. Use the existing pane image-resolution selector for original access. A preview is
not sufficient evidence for unreadable fine text. Image loading, decode, and ready states are
separate from artifact availability; ready records successful decode and two animation frames,
not visibility, fidelity, or acceptance. Navigation discards obsolete image completions.

Previews support admitted single-frame PNG, JPEG, and WebP only. The service bounds compressed
input to 16 MiB, decoded images to 16 million pixels and a 16,384-pixel edge, preview output to
a 1,280-pixel edge without upscaling, and derivative output to 8 MiB. JPEG-source previews
use a disclosed quality-85 JPEG recipe; PNG and WebP previews use PNG. Exact regions use
lossless PNG. At most two image transformations
run concurrently. Unsupported, corrupt, oversized, or changed inputs produce explicit errors.
Pillow and codec versions are included in the serving identity; Python dependencies are in
the repository's `requirements.txt`. Originals remain authoritative. Smaller preview dimensions
do not guarantee fewer encoded bytes or lower model cost.

For exact image detail, Compare URLs use `leftRegion=x,y,width,height` together with
`leftImageSha256=IMAGE_BYTE_SHA256`; the right pane uses the corresponding `rightRegion`
and `rightImageSha256` fields. Coordinates are integer pixel edges in the orientation-normalized
source image, not browser or screenshot coordinates. Bounds are checked without clamping or
scaling. Each pane keeps its own selection; equal coordinates do not establish correspondence.
The existing resolution selector returns that pane to original or preview, serialized as
`leftImage=original|preview` or `rightImage=original|preview`. A pane cannot specify both a
region and an original/preview variant.

The existing stage image endpoint accepts `variant=region&region=x,y,width,height` with
`expected_artifact`, `expected_version`, and `expected_sha256`. Use the image byte digest from
the artifact's `sha256`, not its source-manifest digest. Returned provenance includes original
and normalized dimensions, orientation mapping, requested crop, lossless PNG settings, output
dimensions, and the actual output digest. Region output is bounded to 1,638,400 pixels and
8 MiB. Unsupported sample modes are refused explicitly; original access remains available.

For agents that need a bounded identity/status response first, the existing exact Compare API
accepts `representation=brief`. Its detail handles lead to the full comparison and exact
artifact data. Brief availability reflects the existing admission/projection state; it does
not attest freshly displayed pixels or replace source inspection.

For text review, start with `GET /api/review/v1/works?view=summary&limit=1`.
Each work's `agent_links` provides `compare_text`, `compare_brief`, and location-discovery
URLs with the selected artifact versions already bound. Discovery does not parse the books.
Comparison links appear only when both stages have an explicit selection; otherwise follow
the work/artifact discovery routes and select the exact pair. These links keep the panes
unlinked; they do not infer a matching passage.

Follow `agent_links.compare_text` to get `ocd-corpus-review-text-compare-v1`: the existing
brief's artifact hashes, validation, warnings, and detail handles, plus each pane's `text`
and `next` URL. This is `representation=text` on the existing Compare endpoint. It returns
one bounded segment per pane without duplicating the full document tree and selected-context
body. Follow a pane's `next` to advance that pane independently. An explicitly requested
segment outside the recorded location retains its location warning; wrong identities or
missing locations return no text. Keep those warnings with any review evidence.

```python
import json
from urllib.request import urlopen

def read_json(path):
    with urlopen(origin + path, timeout=60) as response:
        return json.load(response)

work = read_json("/api/review/v1/works?view=summary&limit=1")["works"][0]
pair = read_json(work["agent_links"]["compare_text"])
print(pair["left"]["text"], pair["right"]["text"])
# Inspect warnings and artifact hashes; use detail.target for formatting or images.
```

Text is the readable projection, not exact source bytes. The first content request still
parses and verifies the selected inputs; subsequent requests reuse the bounded in-memory
projection. Metadata discovery and cached projections are admission snapshots. Exact text,
original bytes, and image requests keep their current-byte checks. There is no disk cache
or copied source authority. Using the direct text link avoids a brief-then-full request pair
and the extra serving-identity scan it would require.

For a selected region, a brief describes the requested crop and its governed handle with an
unknown output digest until pixels are generated. The selected image response supplies the
actual derivative identity. Copying reviewed identity preserves the requested image-view
scope and does not by itself attest decode, visible pixels, or acceptance.

Each launcher invocation also has an opaque session identity. The browser exposes the current
session at `GET /api/review/v1/session`, and every response includes an `X-CVW-Request-ID` header.
The Library header shows the bound origin and session identity; failed requests show their code,
HTTP status, request ID, and request path, with retry and copy-diagnostics controls. These are
bounded diagnostics only: CVW has no Notes or Structure screen/protocol, authentication or agent
credentials, event replay, acceptance workflow, or publication authority. TEI-to-Hugging-Face
publication is future work and out of scope for this viewer.

When several agents or browser sessions are running at once, use separate worktrees so each
session has its own built `cvw_app/dist`, and give each launcher invocation its own port (the
launcher defaults to `--port 0`). An explicit fixed port is single-session operator input. When
persistent handoff evidence is useful, give each invocation a fresh `--session-output` directory
outside both the implementation checkout and the input repository, their storage roots,
and the exact candidate/source/static inputs. Repository `reports/_logs` and `.scratch` are
protected destinations and are rejected. The directory receives `<session-id>.events.jsonl` request/preflight
events and `<session-id>.receipt.json` with the latest session state, actual port, catalog and
candidate identities, implementation digest, and preflight timing. CVW does not discover or merge
these directories into a registry.

For a shared checkout that is changing during review, the maintained materializer
can create a fresh external execution copy instead of another full worktree:

```powershell
py -3 -m cvw_app.materialize_runtime --destination "<fresh-runtime-root>" --repository-root "<canonical-input-root>" --catalog "<catalog-path>" --candidate-dir "<candidate-root>"
```

Run this in the context that will launch CVW. It validates the source build,
copies the governed Python closure and built assets without changing their
relative paths, and verifies source/destination bytes and membership. Existing
destinations are refused; a failed partial copy is retained for inspection.
The resulting `cvw-runtime-materialization.json` records the exact file set and
`launch.argv` for the copied protected launcher. Execute that argument array in
the intended host context, adding a fresh `--session-output` path when needed.
Materialization itself starts no server and does not prove host readability or
candidate admission; the successful host launch and its normal session receipt
provide those separate checks.

Canonical inputs stay at their original paths under `--repository-root`.
Unrelated additions outside the copied execution root cannot alter its Python
membership. The normal launcher still detects changed governed members, added
initializers/package shadows, missing files, loaded-origin escape and asset
drift inside that root. The copy is a runtime snapshot, not an input authority;
preserve earlier sessions and receipts when starting a successor.

## Build and test

Install the frontend dependencies as setup:

```powershell
Set-Location cvw_app
npm ci
Set-Location ..
```

Run the currently required verification commands from the repository root:

```powershell
py -3 -m pytest -p no:cacheprovider cvw_app/tests/test_review_work_catalog.py cvw_app/tests/test_native_images.py -q

Set-Location cvw_app
npm test
npm run build
Set-Location ..
```

The frontend scripts are defined in `cvw_app/package.json`.

## Launch

Build the frontend, then launch the Windows loopback service from the repository root. The
launcher defaults to declared work/acquisition sidecars and accepts `--candidate-dir`
repeatedly for caller-selected current-session candidates:

```powershell
py -3 .\cvw_app\launch_windows.py `
  --candidate-dir PATH\TO\candidate-one `
  --candidate-dir PATH\TO\candidate-two `
  --port 0 `
  --session-output PATH\TO\session-evidence
```

Direct script execution pins the implementation import root before CVW imports. When an
isolated worktree reads inputs from another checkout, supply `--repository-root PATH`.
Historical WorkCatalog review additionally requires explicit `--catalog PATH`. The repository root identifies the input/authority repository;
the running script identifies the implementation. Ordinary programmatic imports record an
explicit limitation when pre-import pinning cannot be proved.

Use `--catalog PATH` for the retained historical review route. Missing declared identities
never trigger a catalog fallback. The launcher resolves, preflights and prints every input
with its declared work(s), source-manifest identity,
candidate digest, and passing validation-report digest before binding a socket. It requires an
existing production `cvw_app/dist` (run `npm run build` first),
rejects candidate paths under repository `data`, `ir`, `raw`, `reports`, `exports`, or other
protected roots, waits for `/review` to return the built entrypoint, and only then opens the
browser. It binds to an OS-assigned loopback port by default; `--host` accepts loopback aliases
only. An explicit fixed port is single-session operator input and a collision fails loudly.
`--port 0` asks Windows for an available loopback port and the `CVW_SESSION_READY` line reports the actual URL
and session identity. `--session-output` is optional and writes per-invocation diagnostics as
described above. A
candidate must already contain the validated `package/` and `validation.json` contract: CVW never
discovers, copies, generates, or stores candidates.

Destination and input validation precede diagnostic creation. An initially unusable output
destination fails startup; later diagnostic I/O failures are reported separately without
replacing HTTP results or preventing listener cleanup. Latest receipts are replaced atomically;
append-only event logs remain separate.

The portable implementation digest covers declared local Python members, exact built assets
and runtime versions. The local `CVW_STARTUP_SNAPSHOT` contains import-origin and protected-input
provenance. Serving implementation drift refuses requests and requires relaunch. Ready means
the backend answered its readiness check; browser dispatch, selected-image decode, visual
inspection and human acceptance are separate observations. Entered phases and final outcomes
are printed even without persistent diagnostics.

The Vite development proxy remains pinned to `127.0.0.1:8766` and is dev-only; the production
launcher does not use that proxy and reports its actual loopback origin on `CVW_SESSION_READY`.

## Real-library canary

The opt-in canary derives required format classes independently from every current WorkCatalog
route and its primary-source authority members, then uses the production native-media allow-list
for typed byte checks. Supplied candidates must cover every applicable class, including HTML,
XHTML, plain text, JSON, TEI, PDF, and image, or the canary fails. TIFF and packaged EPUB are the
only classes reported as “not applicable” when absent; if a live route introduces either format,
it is exercised and must pass instead. The browser subtest uses Python Playwright/Chromium to
exercise full-catalog filtering, Paradise Lost's explicit retained-source selection, bounded Read,
independent long-work Compare, and exact identity copy using keyboard controls;
the format matrix also reaches each selected witness through the loopback HTTP service. Ordinary
test runs skip unavailable operator inputs, while required gate mode converts missing inputs or
browser support into a failure so a green-with-skips run cannot be accepted as evidence.

```powershell
$env:OCD_CVW_CANARY_CATALOG = 'reports/publish/work_catalog.json'
$env:OCD_CVW_CANARY_CANDIDATES = 'PATH\TO\current-candidate-one;PATH\TO\current-candidate-two'
$env:OCD_CVW_CANARY_REPOSITORY_ROOT = 'PATH\TO\Open Christian Data' # only when testing from an isolated worktree
$env:OCD_CVW_REQUIRE_REAL_CANARY = '1'
py -3 -m pytest -p no:cacheprovider cvw_app/tests/test_real_library_canary.py -q -s
```

The repository-root override is optional and lets an isolated development worktree read the
operator-selected canonical retained-source root without creating junctions or copying evidence.
The test prints `CVW_REAL_LIBRARY_CATALOG=...`, `CVW_REAL_LIBRARY_CANARY_MATRIX=...`,
`CVW_REAL_LONG_WORK_CANARY=...`, and `CVW_REAL_FULL_CATALOG_CANARY=...` so the bounded 402-work
response, applicable formats, exact witnesses, multi-segment timing, and many-candidate preflight
timing are recorded. The browser workflow uses a 1440-by-1000 viewport and verifies the full
Library, explicit Paradise Lost source selection, every Fisher source/TEI segment, independent
Compare panes, and the copied exact identity without any non-GET request.
# Declared-library migration route

`py -3 -m cvw_app.launch_windows --declared-library --repository-root <repo> --candidate-dir <reviewed-package-root>`
explicitly selects the default work/acquisition-sidecar route without reading
WorkCatalog. The manifest names either one `work_id` or a nonempty, unique, ordered
`work_ids` cohort. Primary authorities may carry `work_ids` to restrict member
association within that cohort. Each work's complete primary-source member set
must match exactly one declared acquisition. Missing identities and ambiguous
associations fail visibly. Existing unbound candidates require an upstream
identity handoff; this option does not repair or re-review them. This route preserves the normal validation and
read-only runtime gates. It cannot be combined with `--catalog`. Historical
catalog launch remains available pending complete corpus migration.

## Engineering boundaries and evidence capture

`renderer_nodes.py` owns the inert document contract, validation, and pagination;
`tei_renderer.py` owns TEI projection; `tei_inline.py` owns mixed-text runs;
`text_decoding.py` owns strict declared-encoding decoding; `ingest_cache.py` owns
bounded process-local projection retention. `review_renderers.py` retains the
registry and compatibility exports. These modules are included in serving identity.
New renderers must satisfy the common contract and have frontend registration.
`src/review/routes.ts` owns exact route parsing, serialization, and navigation;
the React application consumes that interface.

Rendering preserves ordinary emphasis and nested lists. Presentation details in
Read and Compare disclose unsupported typography, note continuity, and inactive
reference targets at bounded locations. The agent brief carries the same limits.
Source stylesheets and full editorial typography are not reproduced. Cached text
is an admitted snapshot; exact access verifies current bytes. Two cold renders may
run concurrently; same-artifact requests share the admitted result. Large cached
projections retain compressed independent pages and contexts, decoded on demand.
Cold parsing still reads the complete artifact; paging is not streaming ingestion.

Capture a ready exact Compare route using the launch receipt:

```powershell
py -3 -m cvw_app.capture_review capture --receipt <session-receipt.json> --url '<exact Compare URL>' --output <fresh-evidence-directory>
py -3 -m cvw_app.capture_review export --source <evidence-directory> --output <fresh-retention-directory>
```

To center exact text independently in each pane, add a JSON target for each side.
Each target names a scope selector, the scope's text prefix, the exact literal, and
its zero-based occurrence. The tool rejects missing or ambiguous scopes, missing
occurrences, route/identity drift, and anchors that remain clipped. Target and
scroll measurements are recorded in `capture.json`:

```powershell
py -3 -m cvw_app.capture_review capture --receipt <session-receipt.json> --url '<exact Compare URL>' --output <fresh-evidence-directory> --left-target '{"scope_selector":"pre","scope_prefix":"Source slot 00004:","literal":"real meaning","occurrence":0}' --right-target '{"scope_selector":"p","scope_prefix":"ORIGINAL PREFACE TO THE NOTES ON THE GOSPELS (BARNES)","literal":"real meaning","occurrence":0}'
```

Omit both target options to retain the original one-viewport behavior.

This optional external client requires Python Playwright/Chromium and Pillow.
It retains the actual Compare response, session descriptor, PNG, hashes, viewport,
route digest, generation, warnings, and errors. It verifies pane identities and
segment ranges before capture and unchanged generation afterward. Export verifies
bytes; neither operation records visual inspection, acceptance, or publication.
A reviewer must inspect the frame and record the actual loci separately. Historical
capture scripts and receipts remain historical; use this receipt-driven entry point
for new captures. Never put capture output inside retained inputs or candidates.

Report a reproducible viewer problem in the contribution's issue or pull
request. Include the session receipt, affected source/TEI locations and warnings;
the [review operations](../docs/SOURCE_TO_TEI_REVIEW_OPERATIONS.md) explain the evidence to retain.

### JSON book reading layouts

JSON sources with explicit `Metadata` and `Data` book records open as articles,
chapters, or numbered questions. Descriptive fields are collapsed under **About
this book**; alternate annotated text and references remain in source-note
disclosures. The matching TEI semantic-tree and explicit catechism layouts use
the reconstructed text itself. Unknown record shapes retain the generic data
view, and the identity-bound original JSON/TEI links retain the complete files.
